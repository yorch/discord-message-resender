discord-message-resender

Capture messages from Discord alert channels in real time, archive them in Postgres, and forward them into a server you control.

View on GitHub Install Configure Run
Read this first. This tool reads channels using your own Discord user token. Automating a user account is against Discord's Terms of Service, and the enforcement outcome is account termination, which would cost you access to every server the account is in. Use it only if you accept that risk. If a source channel is an Announcement channel, Discord's built-in Follow feature mirrors it into your server with no token and no ToS exposure; prefer that where it is available.

What it does

Three services behind one Postgres database. The ingest service holds a live gateway connection, stores every message, and fans matching ones out through Discord webhooks into your own server. A read-only API and web dashboard let you browse and query the archive.

source channels ─▶ ingest ─▶ Postgres (archive) ─▶ query API + dashboard └─▶ webhook ─▶ your own server

Install

You need Docker and just. A Discord account that is a member of the alert servers supplies the token.

git clone https://github.com/yorch/discord-message-resender.git
cd discord-message-resender
just setup   # copies .env and config/routes.yaml from the examples, installs deps

Configure

Edit the two files just setup created.

1. Get your Discord token

  1. Open discord.com/app in a web browser and log in.
  2. Open developer tools (F12) and select the Network tab.
  3. Filter to /api/v, then click a channel so a request appears.
  4. Click any discord.com/api/v* request and read the Authorization request header. That raw value is the token; it has no Bearer or Bot prefix.

The token bypasses two-factor authentication, so treat it like your password. Changing your Discord password revokes it.

2. Fill in .env

Set the database password, DISCORD_USER_TOKEN, one webhook URL per destination channel, and an API_TOKEN for the query API (openssl rand -hex 32). Then confirm the token works:

just check-token

3. Fill in config/routes.yaml

Turn on Developer Mode in Discord to copy server and channel IDs. Each route names a source guild, its channels, and the webhook to forward to. A route with no webhook is archive-only.

Run

just docker-up      # start the stack
just docker-logs    # follow the ingest logs

The log lists each watched channel it resolved at startup. A channel it cannot see means the ID is wrong or the account lost access.

Browse and query

Open the dashboard at http://localhost:4000/ and paste your API_TOKEN. It lists captured messages with their embeds and delivery status, searches, filters by channel, and shows deleted alerts struck through.

Or query the API directly:

TOKEN=$(grep '^API_TOKEN=' .env | cut -d= -f2-)
curl -H "Authorization: Bearer $TOKEN" 'http://localhost:4000/alerts?limit=20'
curl -H "Authorization: Bearer $TOKEN" 'http://localhost:4000/stats'
